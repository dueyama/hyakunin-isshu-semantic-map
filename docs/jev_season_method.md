# Jev・GPTの季節判定と既存埋め込み・文献参照の比較

初回実行・記録日: 2026-09-20。読者向け本文は [補章「季節の色は、意味の地図と重なるか」](paper/seasons/)。

## 入力と分離

- 小倉100首: `data/hyakunin_isshu.csv` の `waka_original` と `waka_kana` を既存の `build_embedding_text(..., "original_kana")` で正規化・改行結合。
- 百人秀歌101首: 非公開の作業用CSVの `waka_original` を同じ関数の `original` 条件で正規化。
- APIに渡すstateは `{"text": "正規化した歌本文"}` のみ。ID、歌人、出典、部立、既存の季節・主題、埋め込みは渡さない。
- Unicode NFKC、空白・句読点等の除去は既存方針を共用。歴史的仮名遣いの現代化、濁点の補完、注釈・訳の追加はしない。
- 小倉と秀歌は入力の表記と読み追加条件が違う。歌集間の分類差を、選歌・部立・季節観の差だけで説明しない。

## Jevへの質問

TypeSafeスキルと [HTTP API](https://docs.typesafe.ai/api)、[Choice](https://docs.typesafe.ai/primitives/choice)、[Noul](https://docs.typesafe.ai/primitives/noul)、[複数判定の構成例](https://docs.typesafe.ai/patterns/composite-scoring)を参照した。

モデルを `jev-1.13.0` に固定し、一首ごとに次の7問を一つのリクエストにまとめる。質問は独立に処理され、他の質問の回答は参照しない。

1. 主な季節: 春、夏、秋、冬、複数季節、季節不特定、判定困難のChoice。
2. 春への言及の有無: Noul。
3. 夏への言及の有無: Noul。
4. 秋への言及の有無: Noul。
5. 冬への言及の有無: Noul。
6. 恋が中心的関心か: Noul。
7. 自然・天候・季節変化の観察が中心的関心か: Noul。

主な季節は、季節の推移では到来した側を選ぶよう指示する。言及判定では、過去・比較・比喩に現れる季節も残す。月、露、悲しみなどから文脈なしに秋を強制しない。質問文は英語、入力本文は日本語。正確な質問は `scripts/jev_seasons.py` の `QUESTIONS` が正本で、SHA-256は集計JSONの `meta.questions_sha256` に記録する。

Choiceの確信度は分布の集中度であって、正解の確率ではない。Noulは条件成立のモデル確率であり、季節の強度ではない。0.6／0.5の境界は探索的な集計用で、古典和歌における校正は未実施。

## 比較方法

### 既存タグ

小倉の初期CSVにある33首の季節タグと一致数を数える。67首の空欄を「季節なし」の正解とみなさない。主題の恋43首・季節33首についても補助的にNoulを集計するが、部立と本文判定は異なる課題である。後から下記の文献参照を追加した。AIへの入力にはこれらの参照ラベルを含めない。

### 既存の意味空間

保存済みの小倉small／largeの本文＋読み、小倉smallの本文のみ、秀歌smallの本文のみを利用する。新しいOpenAI埋め込みの生成は行わない。IDで結合し、全IDの存在・重複・入力ハッシュ・ベクトルを検証する。

H010とH053はそれぞれ `別かれては → 別れては`、`明くるまは → 明くる間は` の過去の表記修正があり、キャッシュは修正前の入力である。記録に基づき修正前表記を再構成すると、保存ハッシュと一致することを確認した。図には旧位置を残して×を付け、近傍統計から除外する。修正済みCSVやベクトルを上書きしない。

PCAは既存の `analyze_embeddings.pca_scores`（seed `20260702`）で再計算する。Jevの回答はPCAに入れない。小倉の左右パネルは同じ座標を使う。秀歌は独立にPCAを計算するため、小倉図の軸・座標と直接比較しない。

### 近傍集計と置換基準

主集計では、Jevが単一の四季を選び、入力ハッシュの一致した歌だけを先に選ぶ。小倉39首、秀歌45首。その集合内で、各歌のコサイン類似度の高い5首を探す。自分自身は除外し、類似度の同点はID順で安定的に解決する。同季節の有向近傍辺の数を全辺数 `5n` で割る。

近傍グラフを固定し、季節ラベルを歌単位でシャッフルする。各クラスの首数は保つ。seedは `20260920`、試行数は10,000。無作為の厳密な期待値は `sum(n_c * (n_c - 1)) / (n * (n - 1))`。片側の置換p値は `(観測値以上の回数 + 1) / (試行数 + 1)`。全ペアを独立標本として扱わず、ペアの無作為抽出もしない。

補助集計は、確信度0.6以上の四季部分集合と、季節不特定を含む入力一致の全体集合。各条件で近傍を作り直すため、率の大小を性能改善として比較しない。小倉small本文のみ条件でもJevラベルは本文＋読みからの同じ回答であり、完全な入力一致の対照ではない。

主集計にはJevの判定による対象選択がある。結果はその部分集合に対する探索的な関連で、全歌への一般化、文学的真偽、因果効果を意味しない。複数のモデル・絞り込み条件を比較しており、p値は多重比較補正を行っていない。共通97首を持つ両歌集や小倉のモデル違いを独立追試として数えない。

## 応答検証と例外

モデルID、回答キー、型、確率の範囲・有限性、Choiceの選択値と最大確率、使用量を検査する。本文・質問・固定モデルを含むリクエスト全体のハッシュをキャッシュキーとし、再開時には同じ入力だけを再利用する。

S053の最初の応答でChoiceの選択値と最大確率の不一致を検出した。内容の良し悪しで選び直したのではなく、応答形式の整合性エラーとして停止し、一度再取得して検証を通過した応答を採用した。最初の応答は検証前保存の実装がなかったため残っておらず、使用量は不明。以後は不整合な応答も非公開の隔離領域に保存して停止する。

有効201応答の入力は239,351トークン、出力35,654トークン。これは最初の無効応答を含む請求全量ではない。同一入力の反復安定性は未検証である。

## 再実行

APIキーは `TYPESAFE_API_KEY` 環境変数を使う。`.env` の自動読み込みはしない。API部分はPython標準ライブラリ、統計比較はNumPy、図の作成はMatplotlibを用いる。

```sh
# 件数と未処理数を確認するだけ。API呼び出しなし。
python3 scripts/jev_seasons.py

# APIを使う実行。保存済みの同一リクエストは再利用。
python3 scripts/jev_seasons.py --execute

# 以降は保存済み応答と既存ベクトルだけを使用。API呼び出しなし。
python3 scripts/compare_jev_seasons.py --figures --public-summary
python3 scripts/test_jev_seasons.py
```

完全な再実行には非公開の秀歌本文・埋め込みキャッシュが必要で、公開cloneだけからの再生成はできない。APIの応答キャッシュと一首ずつのレビューCSVは非公開領域に保存する。公開用の `docs/jev-season-summary.json` は集計値のみ。各首の判定ラベルと文献対応は、本文・ベクトル・認証情報を含まない `docs/season-comparison.json` に別途公開する。

## GPT-5.6-Lunaとの比較

[モデル仕様](https://developers.openai.com/api/docs/models/gpt-5.6-luna)と[構造化出力仕様](https://developers.openai.com/api/docs/guides/structured-outputs)を確認し、APIで利用可能な `gpt-5.6-luna` を指定した。Responses API、`reasoning.effort=medium`、`max_output_tokens=4096`、`store=false`。JSON Schemaで七択の `season` 一つを返す。モデルが生成する説明文・自己申告の確信度は取得しない。

`scripts/gpt_seasons.py` はJevの `QUESTIONS["season"]` の指示文・選択基準と `load_poems()` の本文を共用する。Jevの補助6問は送らない。API形式・質問数・推論設定が異なるので、速度や費用の優劣を比較する実験ではない。いずれも学習時の著名な歌への接触は統制できない。

2026-09-20の実行は201首全件で完了。入力67,539・出力17,854トークンで、全201応答が初回の検証を通過した。小倉はJevと95/100、秀歌は82/101で一致し、GPTの共通歌97首の小倉・秀歌間判定は全て一致した。

取得済み応答は検証前に非公開のattemptとして保存し、完了状態・モデルID・出力スキーマ・使用量を検査してから再利用可能なcacheへ保存する。リクエスト全体のSHA-256で識別し、本文・質問・モデル・推論条件が変われば別リクエストになる。同一リクエストの反復実行はしていない。最大4並列、失敗後は新規投入を止め、自動再試行しない。

`scripts/compare_season_models.py` はモデル間の一致・不一致、七分類のクロス集計、季節を明示した参照資料との一致数、共通97首での歌集間一致を集計する。未実行のGPTは `null` とし、一致率・混同行列・近傍計算から除外する。`--allow-partial` なしでは一件でも未取得があれば停止する。

埋め込みとの追加比較は、両モデルの結果がある同一全体集合と、両モデルが四季を選んだ同一部分集合を先に選び、それぞれで近傍グラフを構成する。小倉の四季共通37首は今回はラベル自体が全て一致したため、近傍統計も同じになる。元のJev単独四季39首の集計との直接的な性能比較は行わない。

```sh

python3 scripts/gpt_seasons.py --execute --corpus ogura
python3 scripts/gpt_seasons.py --execute --corpus shuka

# API呼び出しなし。集計JSONと本文中の結果表を同時更新。

# 未完了状態を明示して出力するときだけ --allow-partial を追加する。
```

## 文献・紹介資料の対応

2026-09-20、[嵯峨嵐山文華館](https://www.samac.jp/search/poems_detail.php?id=1)の小倉100首の各ページで歌番号・部立・出典を照合した。同館が参考文献として掲げる2冊そのものは直接閲覧していない。結果は `docs/season-references.json` に記録。本文・現代語訳・解説文は転載せず、分類の事実と出典URLのみ記録した。

- `reference_season`: 四季の明示32首（春6・夏4・秋16・冬6）。
- `season_annotation`: H026「雑（秋）」を含めた季節注記33首。既存CSVの季節33首と一致した。
- 非四季部立を無季の正解とみなさない。
- 秀歌共通97首は小倉側の対応歌の参照。秀歌の異文の季節を校訂したデータではない。
- 秀歌のみ4首は日文研の和歌DBで出典歌の部立を確認。S053=後拾遺・哀傷536、S073=新古今・春上10、S076=金葉二度本・春50、S090=新古今・恋一1075。S090は語句に異同がある対応歌。

既存CSVとの出典歌番号差には版・番号体系の違いもある。今回の比較は季節・部立を対象とし、本文や出典番号の基礎データは変更しない。

一覧は既公開の参照資料ページの歌を再掲する。秀歌共通97首は小倉の対応歌の表示本文であり、判定に渡した秀歌表記そのものではない。小倉本文はWikisourceのCC BY-SA 3.0という出典条件を引き継ぐ。

## Luna根拠付き条件（別実行）

2026-09-20、`gpt-5.6-luna` に同じ201首を改めて渡し、季節に短い根拠語句と日本語説明を加えた。季節のみ条件を上書きせず、`scripts/gpt_seasons_reasoned.py` と別の非公開キャッシュに保存する。

- 本文、主季節の指示・七択、推論medium、最大出力4096、store=falseは元の条件と共通。前回の結果・Jevの判定・資料の分類はモデルに見せない。
- 追加指示は結論の短い日本語説明を求めるもので、内部思考の逐語記録は求めない。
- 出力schemaは `season`、`evidence`、`explanation` の順。根拠は0〜2個の各8字以内（合計16字まで）、説明は180字以内。HTTP JSONでschemaの項目順を維持し、送ったリクエスト全体を同じ順序でハッシュ化する。元条件の出力項目はseasonのみだった。
- 全201首で初回応答が形式検証を通過した。使用量は入力96,885・出力39,335・合計136,220トークン。説明文や推論トークンも含むため、元条件と同じ出力負荷ではない。
- 変更はH012（季節不特定→秋）、S005（冬→秋）の2首。季節のみ条件との一致199/201、歌集間の共通歌一致は95/97。資料の季節明示との一致は小倉33/33、秀歌34/35。各条件一回なので、差を説明要求の効果と通常の実行変動に分解できない。
- H012の生成説明にある七夕は入力本文にない場面の補足で、確認済みの文学的事実として採用しない。生成説明はモデル出力として掲げる。
